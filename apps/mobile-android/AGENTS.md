# Native Android Guidance

This app owns the fully native Kotlin and Jetpack Compose client. Follow the repository [engineering rules](../../AGENTS.md), [application boundaries](../AGENTS.md), and [cross-app module structure](../../docs/architecture/module-structure.md).
Use the repository [native Android parity skill](../../.agents/skills/android-native-parity/SKILL.md) for Compose/UniFFI feature work and the [cross-client parity skill](../../.agents/skills/cross-platform-module-parity/SKILL.md) when mapping public behavior across clients.

- Keep each screen in `app/src/main/java/com/synapse/features/<module>/ui/` using the canonical module ID. Match feature, action, and typed payload vocabulary with React/Tauri and Qt counterparts where responsibilities correspond; retain Compose conventions (`<Feature>Screen`, ViewModels) and record direct name mappings rather than forcing React or QML directory layouts into Android.
- Add `viewmodel/`, `domain/`, and `data/` packages under that module only when the feature has those responsibilities.
- Keep shared theme, Rust bindings, and media primitives in their shared `com.synapse.ui.theme`, `com.synapse.core`, and `com.synapse.media` packages.
- **Zero Domain Duplication**: Put all platform-neutral business rules, database queries, migrations, habit streaks, balance calculations, quiz evaluations, and FSRS algorithms in `../../core/synapse-core/` and call them strictly through `../../bridges/bridge-uniffi/`. Kotlin ViewModels and Compose screens are thin presentation adapters and must NEVER create custom Room/SQLite schemas or reimplement domain logic in Kotlin.
- Group JVM and instrumentation tests under `app/src/test/` and `app/src/androidTest/` by module.
- Review Android parity independently; the Qt [native desktop parity guide](../../docs/native-desktop-parity.md) does not certify Compose behavior. Keep current testing and security status linked from the [documentation status index](../../docs/documentation-status.md).
- Keep the [active Native Android architecture guide](../../docs/platforms/android-native.md) current whenever an Android capability is audited or changed. Track route, persistence, sync, encryption, and UX acceptance separately; a visible route alone is not feature parity. Record stable, verified architecture and status in `docs/platforms/android-native.md`.
- Treat that checklist's handoff section and feature matrix as the current Android implementation queue; completed historical audit snapshots are not evidence of current parity. Record new build and device acceptance there as work lands.
- Before adding a route or enabling writes, check for an existing `synapse-core` domain and expose it through a typed, cohesive UniFFI store. Do not add sample personal data, placeholder screens that imply working behavior, no-op actions, or Kotlin business calculations to simulate parity.
- New module mutations must use a module-owned repository/ViewModel and the shared Android database path. Preserve the existing database file until an explicit data migration is implemented and verified.
- Anki queue ordering, daily limits, FSRS-6 scheduling (including 17/19/21-weight migration and learning-step progress), and review persistence belong to `synapse-core`; Android must consume them through `SynapseAnkiStore` and must not use `SynapseFsrs` as a substitute for saving a review. Route Tauri writes through the same Core scheduler. The browser's `ts-fsrs` integration remains transitional until parameterized Core/WASM scheduling and numeric parity are verified.
- Keep the React-to-Android Anki checklist honest about browser scheduler migration, note/card templates, media, review history, import/export, and sync until each has a working end-to-end path.
- Question selection, correctness evaluation, attempt persistence, and quiz statistics belong to `synapse-core`; Android must consume them through `SynapseQuestionsStore` and must not calculate answer correctness in Compose or the ViewModel.
- Keep the React-to-Android Questions checklist honest about the implemented Core-backed battery/question CRUD, simulation tag/status/limit/shuffle controls, global recent-attempt history, and question-filtered history. History queries and answer-key lookup belong in `synapse-core`; Android may display the typed result through `SynapseQuestionsStore`. A localized categorized Questions guide exists. Track the separate filtered battery browser, open-answer types, richer analytics, and sync as open until each has a working Android path.
- Notes metadata, page creation/rename, history-aware plain-text saves, pinning, cycle-safe reparenting, sibling reordering, and subtree deletion belong to `synapse-core` through `SynapseNotesStore`. Only edit page bodies Core identifies as unencrypted, non-collaborative plain text; render rich pages read-only and never send encrypted content into the Compose UI. Keep linked-page flows, rich editing, and revision restore marked open until implemented.
- The Home dashboard should combine existing typed Calendar, Anki, Notes, and Finance repository results; keep domain calculations in Core, use Core ordering for pinned/recent pages, and route note selections through the Notes screen instead of duplicating page state.
- Focus timer state is an Android orchestration concern: persist the selected preset, pause state, sound selection, and absolute running deadline locally so navigation and process recreation do not reset a session. Keep completed-session records, recent history, and daily statistics in `synapse-core` through `SynapseFocusStore`; calculate running time from the deadline instead of decrementing a saved counter.
- Focus alarms are canonical Core records and must use `SynapseFocusStore` for list/create/toggle/delete. Android may schedule only the OS alarm and notification; request `POST_NOTIFICATIONS` after an alarm action, disable a triggered alarm through Core, and restore enabled alarms from Core after reboot. Keep delivery precision and cross-device alarm sync marked open until verified.
- Focus Lofi track metadata must use `SynapseFocusStore`; import Android audio with the document picker and a persisted read-only content URI grant, then stream it through Media3 without copying provider data. Keep playback local-only and do not claim encrypted storage or cloud parity. Preserve URI access while a track is in Trash and revoke it only after permanent deletion, checking Core for another Files or Lofi reference. Keep background/global playback, sorting, bulk actions, encryption, and sync marked open.
- Keep native guides for Finance, Focus, Culture, Habits, Library, Questions, Vault, and Trash synchronized with actual Android flows and limitations. The current app source including the Trash guide compiles; device and instrumentation acceptance remain separate gates. Keep guides for other routes open until implemented. Localize new user-facing guide text in English and Brazilian Portuguese.
- Keep the Android Vault non-persistent until it has an audited Android key lifecycle and typed encrypted Core/UniFFI operations. Core Vault CRUD stores supplied strings directly, so never pass credential plaintext to it. Any Vault implementation must account for existing ciphertext and plaintext rows, migrate credential/group/custom-field/password-history fields atomically, zero key material on lock, and verify that decryption failures stay in a locked/error state. Do not claim Android account-key migration, sync, or complete at-rest encryption until each path is implemented and audited.
- Calendar event list/create/edit/complete/delete, event/task types, all-day ranges, recurrence generation/group deletion, date-range validation, reminder offsets, and notified-offset state belong to `synapse-core` through `SynapseCalendarStore`; keep Android forms and repositories as typed adapters, preserve event type and end times, use native Android date/time pickers for ISO inputs, and surface failures instead of dropping database rows. Reconcile deterministic Core notification records with local `AlarmManager` entries, request runtime permission when the user saves reminders, restore alarms on boot and when the app opens, and cancel obsolete alarms after event edits, completion, or deletion. Month navigation and selected-day filtering are presentation concerns; track cross-device reminder sync and encryption separately.
- Notification read/delete/snooze operations belong to `synapse-core` through `SynapseNotificationsStore`; keep snooze source updates and follow-up creation in one Core transaction. Calendar reminder records and delivery state also belong in Core; only the OS alarm, notification permission, and tap intent belong in the Android platform adapter. Persist alarm payloads locally, restore pending alarms on boot and when the app opens, route linked page/event targets from notification rows and system alerts, and cancel alerts when users read/delete a notification or change its Calendar event. Keep cross-device notification/reminder sync marked open.
- Culture item create/edit/progress/goal/delete and episode operations belong to `synapse-core` through `SynapseCultureStore`; map complete `CultureItemRecord` metadata into the Android model and preserve catalog fields when editing only visible form values. Keep API discovery/sync and recommendation calculations out of Compose.
- Library book creation/edit/archive/delete, collection CRUD and assignment, reading-progress transitions, statistics, bookmarks, and highlights belong to `synapse-core`; Android must consume them through `SynapseLibraryStore` and confirm destructive deletion. Android's manual annotation notebook is not a PDF/EPUB reader; keep document import/reading, reader-linked text selection, sync, and local annotation encryption marked open.
- Files folder/item queries, global search, metadata changes, moves, duplication, file type detection, and soft deletion belong to `synapse-core` through `SynapseFilesStore`; Android must not introduce a second file catalog or SQL path. Debounce global searches, cancel stale requests, retain the section filter, and resolve searched folders to their canonical parent path. Bound large file result sets and keep pagination marked open until it works end to end. Use the Android document picker and persisted content-URI grants as the platform storage adapter, open previews with a read-only URI grant, and confirm deletion. Preserve grants through soft-delete for restore, then revoke orphaned grants on permanent deletion or Trash emptying. Keep Drive sync, bulk actions, export, linked-page actions, and file encryption marked open until they work end to end.
- Diagram metadata and catalog CRUD belong to `synapse-core` through `SynapseDiagramsStore`; generate IDs/timestamps in Core and confirm soft deletion. React stores Tldraw snapshots in the shared `diagrams.content` field. Until Android has a compatible document adapter, never write Compose-specific payloads there, block editing non-empty or encrypted web documents, and keep transient native strokes visibly marked as unsaved. Track canvas persistence, interoperable editing, restore, and export as open.
- Android Video metadata, folder CRUD/moves, and playback progress belong to `synapse-core` through `SynapseVideoStore`; keep folder validation and catalog mutations out of Compose. Confirm folder deletion and leave its videos in the unfiltered catalog. For local Android selection, use the document picker, keep a persisted read-only content-URI grant, and stream the selected URI directly without copying it into app storage. Treat provider URIs as provider-managed data; do not claim app-managed encryption or sync. Drive/YouTube, subtitles/audio tracks, vocabulary, restore, key lifecycle, and encrypted ENC1 playback remain open; never put key material in a URI, database field, or log.
- Android display and interaction preferences such as note text size, keyboard spellcheck, card animation, and local study sounds belong to `features/settings` and may use Android preferences storage. Keep them typed and apply them in the consuming screens. Do not expose React settings for accounts, encryption, cloud sync, backup, AI providers, or sharing until the corresponding Android flow is implemented; track local-only behavior separately from cross-device settings parity.
- Put new Android UI text in `res/values/strings.xml` with English defaults and add matching `res/values-pt-rBR/strings.xml` translations. This follows the repository's English-first rule while allowing Android's system locale; it does not replace the still-open in-app language selector and cross-client language sync.
- Native Anki review must retain the Core-owned review ordering and persist ratings through `SynapseAnkiStore`. The focused review supports hardware-keyboard Space to reveal, 1–4 to rate, and Esc to exit; keep the Anki shortcut guide synchronized when changing these keys.

Preserve navigation contracts, accessibility labels, and feature behavior when reorganizing Compose screens.
