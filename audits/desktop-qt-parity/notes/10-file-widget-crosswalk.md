# Notes File-Widget React/Qt Crosswalk

This document compares only the file-attachment widget inside Caderno. It does not audit the standalone Files module. React is the behavior and appearance reference; Qt remains the implementation target.

## Source map

| Responsibility | React Web | Desktop Qt |
| --- | --- | --- |
| Editor node and UI | `apps/web-react/src/components/editor-extensions/FileWidgetBlock.ts` and `FileWidgetNodeView.tsx` | `apps/desktop-qt/qml/notes/FileAttachmentWidget.qml` owns Core-backed state and operations, composed from `apps/desktop-qt/qml/notes/FileAttachmentIdentity.qml`, `FileAttachmentRenameEditor.qml`, `FileAttachmentActionBar.qml`, and `FileAttachmentKeyboardActions.qml`, through `BlockDelegateRouter.qml` |
| Missing-record and delete prompts | `FileWidgetDeletedNoticeModal.tsx`, `FileWidgetDeleteConfirmModal.tsx` | `FileAttachmentMissingDialog.qml`, `FileAttachmentDeleteDialog.qml` |

| File preview | `FileViewer`, `FloatingPdfViewer`, `AudioPlayerModal`, file actions and module navigation | Notes-owned `NotesFilePreviewModal` reuses `FilesPreviewOverlay`; Core prepares a request-scoped protected preview and emits dedicated Notes PDF page results |
| Editor persistence | TipTap node attributes and file API updates | Core `NoteBlock` AST, `FileAttachmentWidget::attrsUpdated`, and `PageView` save flow |

## Data contract

The persisted React-compatible widget uses a stable file ID plus display metadata such as name, file type, size, link flag and color. Qt must preserve the same canonical `data-file-id`, `data-name`, `data-file-name`, `data-file-type`, `data-file-size`, `data-is-link` and `data-color` attributes when editing. `getFileWidgetMetadata` intentionally returns only ID/name/type/size; paths and Drive identifiers remain inside the controller and preview service.

An attachment can outlive its file record because a file can be trashed independently. The widget must distinguish the saved node from the live Core record: missing records stay visible with the stored display name, and restore/change signals refresh the live state without rewriting the note by themselves.

## Current evidence

The file-by-ID metadata adapter, file-change/restore refresh signal, Core-first rename result handling and same-ID attribute synchronization, active/floating/nested PageView preview routes, direct folder navigation, missing-file notice, generic block-delete confirmation and pre-removal rich-text flush have source paths. Audio attachments now have an in-note native MPV player using a request-correlated, Core-prepared temporary file. The Notes-owned text preview now persists reading progress and bookmark CRUD per file ID; its debounce, restore prompt, scroll jump and bookmark changes pass the focused Qt harness. The bookmark control now follows the React header placement with a bookmark icon/count badge, nonmodal 288 px popup and date subtitle; rename moves focus to its field and saves on Enter. Focused harness covers resize, rename focus/save and Escape; full Tab order and screenshot comparison remain open. Markdown attachments can now be edited in a full-canvas source editor; save stages an encrypted replacement and atomically updates the active Core file reference while preserving its ID. The encrypted-files test rejects an oversized replacement without changing the old path, size or readable content; the editor harness covers discard, Tab and Ctrl+S. The Notes text viewer now constrains the reading column to React's 768 px maximum, centers it, wraps raw text, and uses React-sized rendered/raw typography while preserving the previous Files-module layout behind the Notes-only flag. Responsive width has focused harness coverage. Existing Drive copies are not synchronized and remain a tracked parity gap. The shared image preview also avoids decoding hidden image surfaces. Files outside folder/audio still have typed destination gaps. Standalone attachment removal now has Cancel, Unlink and local Trash actions; local soft-delete waits for the page save and is deferred when the saved note still references the file. Trash requests now bubble from toggle, column and collection editors to the owning PageView. File and document-bundle widgets now share a palette with React's colors and native popup placement. The focused controller/QML and native build evidence is listed in [07-verification.md](07-verification.md); live folder selection, playback, vault interruption, focus, matched-viewport behavior and remaining typed viewers stay open. Remote Drive deletion remains open because Qt has no typed native delete service.
