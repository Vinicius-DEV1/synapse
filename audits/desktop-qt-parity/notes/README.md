# Caderno (Notes) React-to-Qt Parity Audit

**Scope:** React Web Caderno module compared with the native Desktop Qt Caderno module. No other product module is in scope.

**Status:** Partial. Source fixes have been applied for several confirmed defects, but the implementation has not passed the focused build, interaction, persistence, accessibility, performance, and same-viewport visual acceptance gates described here. `Partial`, `Missing`, and `Unverified` are evidence labels, not estimates of completion.

## Evidence rules

- React Web is the behavior and visual reference. The Qt application is the implementation target.
- The audit and follow-up review inspected source and existing documentation. Focused `qmllint`, Core/bridge/Qt builds, and one eight-second offscreen application-startup smoke with a disposable database have run. No full Notes page interaction session, screen-reader review, or matched-viewport visual capture has been run; one isolated offscreen palette harness is recorded in [07-verification.md](07-verification.md). Current evidence and limits are recorded in [07-verification.md](07-verification.md).
- Existing checked boxes and historical test totals in other documents are not evidence for the current worktree.
- Features visible in QML are marked `Unverified` until their complete action, error, persistence, and recovery paths are reviewed. Similar-looking controls do not establish parity.
- The audit follows the current Qt Notes source structure, including focused widget components and controller adapters; unrelated modules were not audited.
- Do not change React layout or behavior to make the comparison easier. Shared behavior belongs in `core/synapse-core/` and typed bridges when it is truly platform-neutral.

## Current high-priority defects

1. **Filtered tables need runtime data-integrity verification.** Qt now uses a read-only filtered projection and an indexed Core function that changes only the selected table; failed projections restore canonical content and re-enable editing. Verify autosave, explicit save, page change, failure recovery and reload with filters active. Details: [QT-NOTES-001](04-bug-register.md#qt-notes-001-filtering-can-save-a-filtered-table-projection), [QT-NOTES-005](04-bug-register.md#qt-notes-005-table-filtering-targets-the-first-table-but-strips-rows-from-every-table) and [QT-NOTES-035](04-bug-register.md#qt-notes-035-failed-table-filter-projection-leaves-the-editor-filtered).
2. **Dropped-file import needs runtime verification.** Local non-image drops now use encrypted import, request correlation, a serial queue, canonical file IDs/type/size metadata and a captured canonical cursor offset. If the target block changes during import, insertion is canceled. Verify ordering, failure, vault lock, page switch, cross-client viewer routing, reopen, preview and the stale-target path. Details: [QT-NOTES-002](04-bug-register.md#qt-notes-002-dropped-files-create-unresolvable-attachments) and [QT-NOTES-034](04-bug-register.md#qt-notes-034-dropped-file-widgets-lose-the-imported-file-type).
3. **Rich-text insertion offsets have Core/Qt source fixes and need runtime acceptance.** Core counts UTF-16 units, modeled block separators, void elements and page-reference atoms, then decodes HTML5 named/numeric references. The Qt adapter maps expanded page labels back to one source atom. Confirm it against `QTextDocument`, especially table cells/rows, hard breaks, object positions and cursor boundaries. Details: [QT-NOTES-003](04-bug-register.md#qt-notes-003-rich-html-split-uses-a-different-character-unit-than-qt) and [07-verification.md](07-verification.md).
4. **Color/highlight marks and table/group metadata have source fixes awaiting cross-client acceptance.** Details: [QT-NOTES-004](04-bug-register.md#qt-notes-004-block-colors-are-not-round-trip-safe), [QT-NOTES-006](04-bug-register.md#qt-notes-006-column-changes-can-discard-group-or-child-metadata), and [QT-NOTES-009](04-bug-register.md#qt-notes-009-table-column-movement-rewrites-row-markup).
5. **Slash command argument handling has source fixes awaiting interaction acceptance.** Qt now extracts linked-page, focus, alarm, event, habit, and Scrap arguments instead of keeping command text or dropping the Scrap URL. See [QT-NOTES-010](04-bug-register.md#qt-notes-010-slash-command-arguments-do-not-reach-native-setup-flows) and the [command crosswalk](08-slash-command-crosswalk.md).
6. **The `/foco` and `/alarme` source outcomes now match React.** Qt starts the global focus timer and saves an active alarm; adding a focus widget or linking an existing alarm remains a separate Notes action. Verify runtime timer/alarm state, cancellation, scheduling, feedback and persistence before closing [QT-NOTES-013](04-bug-register.md#qt-notes-013-focus-and-alarm-slash-actions-have-different-outcomes).
7. **Widget attribute round-trip needs validation.** The shared Qt escaping helper now covers dynamic labels, URLs, column metadata, plain-text imports and file-size attributes; file sizes are normalized before serialization. Verify metadata round-trip and same-value rendering in Qt and React. See [QT-NOTES-014](04-bug-register.md#qt-notes-014-widget-html-interpolation-does-not-consistently-escape-entity-characters).
8. **Alarm setup needs its input constraints checked in the running UI.** The Qt form now validates `HH:mm` and caps the optional label at 30 characters; record behavior for partial typing and persistence. See [QT-NOTES-015](04-bug-register.md#qt-notes-015-native-alarm-setup-accepts-invalid-time-strings).
9. **Scrap capture validates the full URL before starting.** Qt now rejects a valid-looking domain prefix followed by invalid text and keeps it editable; verify no request is sent for invalid input. 10. **Calendar event creation now links the note widget to Core.** The returned event/page IDs and React's form defaults are implemented in Qt, but creation and round-trip behavior still need runtime verification.
