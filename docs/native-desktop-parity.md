# Native Desktop Parity Tracker

This tracker compares the React application with the Qt desktop client. A QML screen alone does not count as parity: each user action must have a native presentation, native orchestration, native persistence, and equivalent failure handling.

## Acceptance Gates

A module is complete only when all of the following are checked against the React implementation:

- Every entry point, control, shortcut, context action, empty state, loading state, and error state has an equivalent native flow.
- Reads and writes use the canonical SQLite database and preserve the existing schema, soft-delete behavior, and encryption envelope.
- Visual layout, spacing, colors, typography, icon shapes, hover/focus states, and dialogs have been compared at the same viewport and density.
- Large collections, keyboard navigation, cancellation, and error recovery have been reviewed.
- The Qt application builds and the native flows have focused automated or manual verification.

Encryption status is tracked separately in [the native encryption audit](./security/native-encryption-audit.md). A configured keychain or an encrypted media import does not mean every SQLite table, metadata field, or pre-existing local file is encrypted.

Qt vault setup now encrypts referenced, readable media in the managed `files/`, `library/`, and `videos/` directories using a persistent recovery journal. Setup stops if a referenced file is outside its managed directory. This closes only the managed-media setup gap; the encryption audit records remaining plaintext database fields, metadata, and cross-client recovery work.

### Questions work item: summary and review wiring

- Expected: completing a session opens its results; selecting a result restores the recorded answer, advancing or exiting review returns to the summary, and restarting clears the session without duplicating attempts. Session shortcuts must not act on the summary or explorer.

## Current Native Build

The baseline desktop target is `apps/desktop-qt/`. The Linux desktop build currently requires Qt 6, libmpv, and libarchive. Native PDF page rendering also requires Poppler command-line tools (`pdfinfo`, `pdftoppm`, and optionally `pdftotext`) on `PATH`; audio-track metadata enrichment uses optional `ffprobe`. Packaging these tools for end-user installs remains open. `SYNAPSE_DATABASE_PATH` can point the executable at an isolated SQLite file for UI checks.

The focused native priority-module test covers editor history, files, encrypted video import/playback lifecycle, EPUB metadata and cover extraction, Open Library metadata parsing, EPUB chapter reading, full-text search across EPUB chapters and selectable PDF pages, native PDF rendering/text extraction, Library reading sessions/statistics and annotations, ffprobe audio-track metadata extraction, and vault-removal migration. This tracker remains open until every row is verified against the original app.

The focused native priority-module tests are opt-in:

```bash
cmake -S apps/desktop-qt -B apps/desktop-qt/build -DSYNAPSE_BUILD_NATIVE_TESTS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build apps/desktop-qt/build --config Release --target synapse-desktop-tests
ctest --test-dir apps/desktop-qt/build -R native-priority-modules --output-on-failure
```
