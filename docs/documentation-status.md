## Verified Project Status

- **Multi-Target Repository**: Contains React Web/Tauri (`apps/web-react/`), native Qt desktop (`apps/desktop-qt/`), native Kotlin/Compose Android (`apps/mobile-android/`), and an Expo/WebView Android shell (`apps/mobile-webview/`). The root npm workspace delegates to `apps/web-react/`; other app targets use their own build systems.
- **Unified Domain Core (`core/synapse-core/`)**: Owns canonical domain models, SQLite schema/migrations, repository persistence, and shared business calculations. Qt controllers and documented Android feature stores delegate through typed bridges. React/Tauri still has audited command paths that bypass Core; the current remediation inventory is recorded under `WEB-CORE-*` in the [Android parity checklist](./audits/mobile-android-parity/README.md), so complete Tauri delegation is not yet achieved.
- **React Web & Tauri Desktop Performance Architecture (2026-11-21)**:
  - **Tauri Backend Concurrency**: Replaced the single global SQLite mutex with a dedicated writer connection and a 4-connection read-only WAL pool (`SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_NO_MUTEX`) with `cache_size = -64000`, `temp_store = MEMORY`, and `mmap_size = 268435456`. Converted 231 Tauri commands to non-blocking `async fn` handlers backed by `tokio::task::spawn_blocking`. Migrated `encrypted://` to `register_asynchronous_uri_scheme_protocol` with strong `ETag` and `304 Not Modified` support (gated by active vault unlock validation).
  - **Lightweight Notes Metadata & Focus Isolation**: `getAllPages` / `notes_get_all_pages` now fetches lightweight metadata only, hydrating `content`, `encrypted_content`, and `crdt_state` on demand via `getPageContent(pageId)` with in-flight request deduplication. Removed full-table reloads on `window.focus` and gated editor/dashboard listeners by `isActive`.
  - **React Store & Context Isolation**: Migrated all 43 former monolithic `useStore()` consumers to fine-grained `useStoreSelector`, `usePages`, `useStoreDispatch`, and `getStoreState`. Isolated 1Hz Pomodoro countdown ticks into `FocusTimerTickContext` and separated `TaskStateContext` from `TaskActionsContext`.
  - **Sync Engine & Bundle Reduction**: Added transactional batch upserts (`sync_upsert_rows_batch` / `upsertRowsBatch`), SQLite and IndexedDB v29 timestamp indexes (`updated_at`, `created_at`, `deleted_at`), on-demand Highlight.js/Lowlight language loading, and Yjs snapshot compaction (>128 KB). Initial boot preloaded JS in `dist/index.html` dropped from **~3.4 MB to ~616.3 KB (-82%)**, passing all 7 CI budgets in `npm run check:budgets`.
- **Qt Desktop Feature Parity**: The React client remains the visual and functional reference. The habits feature is an embedded editor widget (`/habito` slash command and interactive widget) in both React and Qt rather than a standalone sidebar route.
- **Cloud Synchronization**: Scoped reconciliation and authenticated decrypted readback are complete according to the [Firebase audit](./audits/firebase-sync-integrity-2026-11-17/README.md) (5,005 scoped sync documents verified, zero missing or remote-only IDs). A fresh React Web account sign-in and full sync pull also completed after the latest Hosting release (5,030 app-recorded reads, 5 writes, no sync error or emergency stop). Source-root documents, archives, and rollback snapshots remain preserved pending separate retention gates.
- **Native Vault & Encryption Coverage**: Partial coverage. Qt setup migrates referenced media inside managed directories with an atomic recovery journal, and React/Tauri/WebView support Firebase account password key rewrapping. However, sensitive business-data columns in several SQLite tables (Finance, Calendar, Habits, Culture, Anki, Questions, Focus, Notifications, Tutor) and metadata fields remain plaintext at rest. The [native encryption audit](./security/native-encryption-audit.md) remains open.
- **Native Android Status**: All 18 canonical route IDs are present. The latest `:app:compileDebugKotlin` passed with JDK 17.0.21.1 and the installed Android SDK; the Gradle task built the UniFFI Rust bridge for `arm64-v8a`, `x86_64`, and `armeabi-v7a`, regenerated Kotlin bindings, and compiled the current source including the Trash guide. Instrumentation and device acceptance remain open. An initial attempt with Android Studio JDK 25.0.3 failed before source compilation because the pinned Gradle 8.9 wrapper rejected that runtime; the setup guide correctly specifies JDK 17.
  - **Core-backed local flows**: Finance, Files metadata, Calendar, Culture, Diagrams catalog, Video metadata/folders/progress, Focus records and alarms, Habits, Trash, Notifications, Practice, Anki, Questions, Library, and supported Notes operations use typed Core APIs through UniFFI. Home reads the agenda, due Anki count, pinned/recent Notes, and Finance summary. Focus timer lifecycle preferences and SAF URI grants use Android platform storage.
  - **Files, notifications, and reminders**: Files supports transactional multi-file SAF import, persisted read grants, Core-backed duplication, and debounced global file/folder search bounded to 500 file results. Notifications support atomic 15-minute snooze, Calendar reminder alarms, reboot/app-start restoration, linked Notes/Calendar navigation, and cancellation on read/delete. Pagination, Drive sync, export, folder import, bulk actions, native preview, cross-device reminder state, and encryption remain open.
  - **Remaining product gaps**: Practice lacks provider calls, interview setup, attachments, and voice sessions. Focus ambient choices do not play audio; exact-time alarms and global/background playback need device acceptance. Culture search/sorting/recommendations, Habits heatmap/note-widget selector, advanced Anki, rich Notes, the Library reader, interoperable diagram editing, encrypted/remote Video, broad Settings, workspace/sharing/AI, and auth/sync remain open. Categorized guides exist for Finance, Focus, Culture, Habits, Library, Questions, Vault, and Trash; other routes still need guides. The Trash guide has 226 matching English/pt-BR resource keys and compiles in the current app build. A static copy scan found at least 345 direct Compose text literals across 60 Kotlin files; broad EN/pt-BR UI localization remains incomplete. See the [Android localization inventory](./audits/mobile-android-parity/ux-and-acceptance.md) for the source scan and remaining localization work.
  - **Security boundary**: Android Vault intentionally remains empty because there is no audited Android key lifecycle, encrypted Core/UniFFI operation, or migration. Existing Core Vault CRUD stores passed values as-is. Finance and other local records are not covered by complete at-rest encryption; never describe app-private storage as encryption.
  - **Current implementation queue**: The [Android parity checklist](./audits/mobile-android-parity/README.md) is the detailed, living comparison and handoff for the next implementation pass. It also records React/Tauri writes that still bypass shared Core repositories.
- **Android Diagrams Status**: The catalog now uses shared Core/UniFFI list/create/soft-delete operations with confirmed deletion. The Compose canvas remains transient, warns that strokes are unsaved, and blocks non-empty or encrypted Tldraw documents until an interoperable native editor is available.
- **Android Video Status**: The catalog lists Core-backed metadata and folders, adds SAF-selected `content://` sources with persisted read grants, plays those URIs through Media3, offers resume/start-over, and persists progress/duration through Core. Android supports folder create/filter/rename/delete and moving videos; deleting a folder keeps its videos in the unfiltered catalog. It does not copy or encrypt these media files; encrypted ENC1/Drive/YouTube playback, subtitles, audio tracks, vocabulary, restore, and key migration remain open.

## Documentation Update Rules

1. Write technical documentation in English. Keep `README.pt-BR.md` as the localized Portuguese README.
2. Use paths relative to the Markdown file for repository links. Do not add machine-specific `file://` links or personal database locations.
3. Update the relevant source-of-truth document in the same change as a feature, migration, performance, or security change.
4. Use `Partial`, `Missing`, or `Unverified` when acceptance evidence is incomplete. Avoid `100%`, `Production`, or fixed test totals unless reproducible current evidence supports the claim.
5. Validate links, commands, paths, and code references against the checked-out repository before reporting completion.
