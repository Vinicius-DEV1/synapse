# Caderno (Notes) React-to-Qt Parity Audit

**Scope:** React Web Caderno module compared with the native Desktop Qt Caderno module. No other product module is in scope.

**Status:** Partial. Source fixes have been applied for several confirmed defects, but the implementation has not passed the focused build, interaction, persistence, accessibility, performance, and same-viewport visual acceptance gates described here. `Partial`, `Missing`, and `Unverified` are evidence labels, not estimates of completion.

## Evidence rules

- React Web is the behavior and visual reference. The Qt application is the implementation target.
- The audit and follow-up review inspected source and existing documentation. A focused `qmllint` pass and Core/bridge/Qt builds have run; no test suite, QML runtime, screen-reader review, or visual capture has been run. Current evidence and limits are recorded in [07-verification.md](07-verification.md).
- Existing checked boxes and historical test totals in other documents are not evidence for the current worktree.
- Features visible in QML are marked `Unverified` until their complete action, error, persistence, and recovery paths are reviewed. Similar-looking controls do not establish parity.
- The audit follows the current Qt Notes source structure, including focused widget components and controller adapters; unrelated modules were not audited.
- Do not change React layout or behavior to make the comparison easier. Shared behavior belongs in `core/synapse-core/` and typed bridges when it is truly platform-neutral.

## Current high-priority defects

1. **Filtered tables need runtime data-integrity verification.** Qt now uses a read-only filtered projection and an indexed Core function that changes only the selected table. Verify autosave, explicit save, page change, and reload with filters active. Details: [QT-NOTES-001](04-bug-register.md#qt-notes-001-filtering-can-save-a-filtered-table-projection) and [QT-NOTES-005](04-bug-register.md#qt-notes-005-table-filtering-targets-the-first-table-but-strips-rows-from-every-table).
2. **Dropped-file import needs runtime verification.** Local non-image drops now use encrypted import, request correlation, a serial queue, canonical file IDs and a captured canonical cursor offset. If the target block changes during import, insertion is canceled. Verify ordering, failure, vault lock, page switch, reopen, preview and the stale-target path. Details: [QT-NOTES-002](04-bug-register.md#qt-notes-002-dropped-files-create-unresolvable-attachments).
3. **Rich-text insertion offsets have Core/Qt source fixes and need runtime acceptance.** Core counts UTF-16 units, modeled block separators, void elements and page-reference atoms, then decodes HTML5 named/numeric references. The Qt adapter maps expanded page labels back to one source atom. Confirm it against `QTextDocument`, especially table cells/rows, hard breaks, object positions and cursor boundaries. Details: [QT-NOTES-003](04-bug-register.md#qt-notes-003-rich-html-split-uses-a-different-character-unit-than-qt) and [07-verification.md](07-verification.md).
4. **Color/highlight marks and table/group metadata have source fixes awaiting cross-client acceptance.** Details: [QT-NOTES-004](04-bug-register.md#qt-notes-004-block-colors-are-not-round-trip-safe), [QT-NOTES-006](04-bug-register.md#qt-notes-006-column-changes-can-discard-group-or-child-metadata), and [QT-NOTES-009](04-bug-register.md#qt-notes-009-table-column-movement-rewrites-row-markup).
5. **Slash command argument handling has source fixes awaiting interaction acceptance.** Qt now extracts linked-page, focus, alarm, event, habit, and Scrap arguments instead of keeping command text or dropping the Scrap URL. See [QT-NOTES-010](04-bug-register.md#qt-notes-010-slash-command-arguments-do-not-reach-native-setup-flows) and the [command crosswalk](08-slash-command-crosswalk.md).
6. **The `/foco` and `/alarme` source outcomes now match React.** Qt starts the global focus timer and saves an active alarm; adding a focus widget or linking an existing alarm remains a separate Notes action. Verify runtime timer/alarm state, cancellation, scheduling, feedback and persistence before closing [QT-NOTES-013](04-bug-register.md#qt-notes-013-focus-and-alarm-slash-actions-have-different-outcomes).
7. **Widget attribute round-trip needs validation.** The shared Qt escaping helper now covers dynamic labels, URLs, column metadata, plain-text imports and file-size attributes; file sizes are normalized before serialization. Verify metadata round-trip and same-value rendering in Qt and React. See [QT-NOTES-014](04-bug-register.md#qt-notes-014-widget-html-interpolation-does-not-consistently-escape-entity-characters).
8. **Alarm setup needs its input constraints checked in the running UI.** The Qt form now validates `HH:mm` and caps the optional label at 30 characters; record behavior for partial typing and persistence. See [QT-NOTES-015](04-bug-register.md#qt-notes-015-native-alarm-setup-accepts-invalid-time-strings).
9. **Scrap capture validates the full URL before starting.** Qt now rejects a valid-looking domain prefix followed by invalid text and keeps it editable; verify no request is sent for invalid input. See [QT-NOTES-016](04-bug-register.md#qt-notes-016-scrap-url-detection-accepts-a-domain-prefix-with-trailing-invalid-text).
10. **Calendar event creation now links the note widget to Core.** The returned event/page IDs and React's form defaults are implemented in Qt, but creation and round-trip behavior still need runtime verification. See [QT-NOTES-017](04-bug-register.md#qt-notes-017-calendar-event-card-is-not-linked-to-the-created-event) and [QT-NOTES-018](04-bug-register.md#qt-notes-018-event-setup-fields-and-defaults-differ-from-react).
11. **Linked event actions now use Core and native confirmation.** Status and title/date edits persist through the controller; event removal asks first and respects unlinked, missing, and expired records. Removing an active recurring event explicitly deletes its linked series; removing an expired event keeps the series. Widgets now load one event by ID through Core and refresh on native calendar mutations. The anchored popover includes reminder/color controls and an “Abrir na Agenda” action; hover shows move-up/down actions and the widget has React-equivalent live-event timing. These source fixes still need runtime, nested-navigation, persistence, and visual acceptance. See [QT-NOTES-019](04-bug-register.md#qt-notes-019-event-widget-status-changes-are-not-persisted), [QT-NOTES-020](04-bug-register.md#qt-notes-020-calendar-record-color-overrides-widget-color), [QT-NOTES-021](04-bug-register.md#qt-notes-021-removing-an-event-widget-bypasses-reacts-confirmation-and-expiry-rules), [QT-NOTES-022](04-bug-register.md#qt-notes-022-event-editing-only-updates-the-inline-widget), [QT-NOTES-023](04-bug-register.md#qt-notes-023-event-popover-blocks-the-entire-notes-window), [QT-NOTES-024](04-bug-register.md#qt-notes-024-event-popover-cannot-open-the-linked-calendar-record), [QT-NOTES-025](04-bug-register.md#qt-notes-025-event-widget-lacks-hover-reorder-actions), [QT-NOTES-026](04-bug-register.md#qt-notes-026-live-events-lack-reacts-time-window-highlight), [QT-NOTES-027](04-bug-register.md#qt-notes-027-recurring-event-widget-deletion-leaves-orphaned-occurrences), [QT-NOTES-028](04-bug-register.md#qt-notes-028-unlinked-event-widget-cannot-be-removed), and [QT-NOTES-029](04-bug-register.md#qt-notes-029-linked-event-widgets-scan-a-capped-calendar-list).
12. **Page references now use native inline atoms.** Qt converts the canonical empty `span[data-page-id][title]` into a one-position `QTextObjectInterface` object with active/deleted chips, selects the whole object on click, opens active references in the floating preview, confirms removal, replaces a selected object when typing, and serializes back to the canonical span. Clipboard copy includes plain title, canonical HTML and a Qt custom MIME payload; paste accepts the custom payload or a single canonical span inside React's ProseMirror/HTML clipboard wrappers. Runtime hit testing, exact visual/accessibility parity, cross-client clipboard behavior, undo, and save/reload remain unverified. See [QT-NOTES-030](04-bug-register.md#qt-notes-030-editing-a-native-page-reference-label-can-lose-text).
13. **Adjacent identical reference objects are serialized individually.** Qt may coalesce neighboring objects with identical formatting into one `QTextFragment`; the serializer now emits one canonical span for each object replacement character. Compile and source review cover the fix; verify actual fragment coalescing and React/Qt round-trip at runtime. See [QT-NOTES-031](04-bug-register.md#qt-notes-031-adjacent-identical-page-references-can-be-lost-during-serialization).
14. **Page-reference presentation follows live page metadata.** Open Qt notes now refresh referenced titles and active/deleted appearance when the page tree changes, including a page restored from Trash, without rewriting note HTML. Verify rename, trash, restore, keyboard/copy actions, dirty-state, undo, and nested-editor behavior before closing [QT-NOTES-032](04-bug-register.md#qt-notes-032-open-page-reference-chips-do-not-refresh-after-target-changes).
15. **Deleted page-reference labels match React's status text.** Native deleted chips now append ` (Excluída)` and include it in their measured width while keeping the stored title untouched. Same-viewport appearance and restoration behavior remain unchecked; see [QT-NOTES-033](04-bug-register.md#qt-notes-033-deleted-page-reference-chips-omit-reacts-status-suffix).
