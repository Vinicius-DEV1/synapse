# Caderno Qt Bug Register

Findings are based on source inspection of the active worktree. Severity is based on content integrity and the normal user path. Fix status must be updated only after a source re-review and the corresponding focused verification.

## QT-NOTES-001: Filtering can save a filtered table projection

- **Severity:** High; possible silent content loss.
- **Evidence:** `apps/desktop-qt/qml/notes/NotesTableExcelGrips.qml`, `applyVisualFilterEvaluation()` assigns filtered HTML to `textEditor.text`. `apps/desktop-qt/qml/notes/NotesRichTextInput.qml`, `onTextChanged`, marks ordinary text changes pending and restarts the commit timer. `NotesRichTextEditor.qml`, `commitEditorText()`, serializes the live `QTextDocument` back to `sourceHtml`.
- **Reproduction:** Open a note with a table, filter out one or more rows, then wait for autosave or trigger a save/navigation path before clearing the filter. Reopen the note and check whether hidden rows remain. Editing while a filter is active also risks serializing only visible rows.
- **Root cause:** A presentation-only filtered projection is written into the same document model and commit lifecycle used for canonical edits.
- **Required fix:** Make filtered HTML an explicitly read-only projection; suppress dirty tracking for programmatic projection swaps; restore the original unfiltered document on clear or page change. Project only the selected table in Core.
- **Acceptance:** Filtering never changes saved source; save/close/reload while a filter is active retains all original rows; filtering a second table affects only that table; visible rows and table schema match React.
- **Fix status:** Source fix applied in `NotesTableExcelGrips.qml`, `NotesRichTextInput.qml`, and `NotesRichTextEditor.qml`. The projection is read-only, suppressed from dirty tracking, and generated by a table-indexed Core function. Save, navigation, and reload acceptance still needs runtime verification.

## QT-NOTES-002: Dropped files create unresolvable attachments

- **Severity:** High; the inserted attachment cannot resolve to stored file content.
- **Evidence:** `apps/desktop-qt/qml/notes/Editor.qml` drop handler inserts `data-type="file-widget"` with `fileName` and `fileUrl`. `FileAttachmentWidget.qml` resolves a file via canonical `data-file-id`/`fileId`, and previews only when a Core file ID exists. `NotesMediaWidgetPickerModal.qml` already uses `importLocalFile()` and inserts canonical `data-file-id`, `data-name`, `data-file-name`, `data-file-type`, and `data-file-size` attributes after import.
- **Reproduction:** Drag a non-image file from the OS onto a note and click the resulting card. The card has no file ID and no registered encrypted file to preview.
- **Root cause:** The editor bypasses the file import/persistence pipeline and writes raw path-like attributes that are not part of the React-compatible file widget schema.
- **Required fix:** Route local dropped files through the same encrypted import flow as the picker; after a successful import, insert the returned Core file ID and canonical metadata. Reject non-local URLs safely. Handle multiple files in a serialized queue because the controller permits one file operation at a time. Surface failure and cancellation without inserting a broken widget.
- **Acceptance:** Local drops produce valid file records and canonical widgets; reopen/preview/export/delete/rename work; failed/locked imports add no widget; image drops continue through image import; multiple-file order is stable.
- **Fix status:** Source fix applied: dropped local non-image files now use the encrypted import pipeline, request IDs, a serial queue, and canonical file widget attributes. Import failure and page/block changes prevent broken insertion. QML signal ordering, multi-file order, vault lock handling, and reopen/preview acceptance remain unverified.

## QT-NOTES-003: Rich HTML split uses a different character unit than Qt

- **Severity:** High; insertion can split text at the wrong position.
- **Evidence:** `BlockListEditor.qml` passes `TextArea.cursorPosition` to `controller.splitRichHtml()`. Qt positions are UTF-16 code-unit offsets. `core/synapse-core/src/domain/notes/block_ast/serializer.rs` increments `count` once per Rust `char`, which counts a supplementary emoji as one scalar value rather than two UTF-16 code units.
- **Reproduction:** Type `A😀B`, put the caret after the emoji, invoke a slash widget command, and inspect the split/inserted HTML and caret.
- **Root cause:** The FFI contract does not state its offset unit; Qt and Rust use different string indexing units.
- **Required fix:** Define the Core split API offset as UTF-16 code units and map rendered Qt paragraph separators, line breaks, and entity references to source HTML offsets.
- **Acceptance:** Insert at every caret boundary around BMP characters, supplementary characters, combining marks, paragraph breaks and HTML entities without character loss, duplication, malformed tags, or caret drift.
- **Fix status:** Partial source fix: Rust scalar iteration now counts UTF-16 code units, and numeric entities use their decoded scalar width. Mapping of paragraph separators, breaks and all named entities is still incomplete; do not close this issue until those offsets are mapped and checked.

## QT-NOTES-004: Block colors are not round-trip safe

- **Severity:** Medium; visual formatting can disappear after save/reload.
- **Evidence:** `BlockDragDrop.js`, `applyBlockColorHtml()`, writes inline `color` or `background-color` styles on a block root. `core/synapse-core/src/domain/notes/html_normalizer/mod.rs` keeps only `white-space:pre-wrap` for paragraph tags and emits plain `<p>` otherwise. React's `useBlockHandle.ts` uses mark-based text color/highlight commands rather than this Qt paragraph-style path.
- **Reproduction:** Apply a text/background color through the Qt block handle, save, reload, and compare. Also open/save in React and compare retained styling.
- **Root cause:** Qt emits a paragraph style that Core's canonical normalizer discards; the clients use different semantic representations.
- **Required fix:** Match React's semantic text color/highlight marks for the block action. Keep the Core style/color allowlists narrow and do not retain arbitrary CSS.
- **Acceptance:** Color and highlight survive Qt save/reopen and React round-trip; clear/reset matches React; unsafe CSS is rejected.
- **Fix status:** Source fix applied: the Qt block action now emits inline `span` text-color marks and `mark` highlight marks; Core retains their sanitized React-compatible color attributes. Empty-block stored-mark behavior and React open/edit/save round-trip remain unverified.

## QT-NOTES-005: Table filtering targets the first table but strips rows from every table

- **Severity:** High; incorrect filter output and risk of collateral edits.
- **Evidence:** `evaluate_table_filter()` in Core derives column types from the given fragment's table parsing; the Qt caller passes the entire rich HTML. `TableGripsHelpers.js:filterTableRowsHtml()` applies one shared row index to every `<tr>` in the whole fragment. `NotesTextOperations::richTableGeometry()` reports the active table geometry but no table identity/index.
- **Reproduction:** Put two tables in one rich-text slice with different row counts, focus the second table, and filter a value that matches one row. Observe which table is evaluated and which rows are hidden.
- **Root cause:** The filter contract is whole-fragment HTML with implicit first-table evaluation, while the UI action is scoped to the table under the caret.
- **Required fix:** Carry active table index through the bridge and make Core parse/evaluate/project only that table. Keep the projection separate from canonical content. Use that index for schema, validation, movement and filtering.
- **Acceptance:** Filtering any table in a multi-table note affects only that table; headers, spans, schema and other tables remain byte-preserved.
- **Fix status:** Source fix applied: Qt rich-table geometry reports the active table index; Core bridge operations use it for column schema, validation, projection, row/column movement and width updates. Multi-table runtime acceptance remains unverified.

## QT-NOTES-006: Column changes can discard group or child metadata

- **Severity:** Medium; custom group or child metadata can be lost during drag, resize, or reorder.
- **Evidence:** `BlockDragDrop.js` rebuilds column wrappers in `serializeColumnsGroup()`. `NotesColumnLayout.qml` calls that serializer during resize, balance and reorder. React's `appendToGroupInTr()` retains group attributes and child attributes while redistributing widths equally.
- **Reproduction:** Add custom `data-*` attributes to a group/column, then resize, reorder, or drag another block into the group. Compare saved attributes and widths.
- **Root cause:** Qt regenerated every child wrapper from only its body and width and created a new group without the old attributes/ID.
- **Required fix:** Preserve existing group attributes/ID and child opening-tag attributes while updating width. When adding a column, redistribute widths equally to match React.
- **Acceptance:** Resize, reorder, and drop preserve all unrelated group/child attributes and content; widths follow React's equal redistribution on add; undo restores the previous structure.
- **Fix status:** Source fix applied: Qt retains the group attributes/ID and existing child opening tags across layout operations, updating only width and flex style. Static-source review passed; drag/resize/undo runtime acceptance remains unverified.

## QT-NOTES-007: HTML attribute decoding is incomplete for AST values

- **Severity:** Medium; uncommon entities can be rendered or reserialized literally.
- **Evidence:** `block_ast/helpers.rs::html_unescape()` decodes only `quot`, `#39`, `lt`, `gt`, and `amp`. Numeric references, non-breaking spaces and named entities may remain encoded when parser values are used by QML widgets or code.
- **Reproduction:** Load custom-widget attributes and text containing decimal/hex numeric entities, `&nbsp;`, and accented/supplementary characters; edit another block and save the page.
- **Root cause:** The parser's entity decoder is a small fixed replacement list.
- **Required fix:** Use a standards-compliant HTML entity decoder or a bounded decoder with a documented supported set. Avoid double-decoding and preserve literal unknown entities.
- **Acceptance:** HTML parse/serialize preserves rendered values and canonical escaping for supported named and numeric entities; malformed entities do not panic or corrupt neighboring attributes.
- **Fix status:** Source fix applied: numeric decimal/hex references and documented common named entities decode in one pass, unknown/malformed names remain literal. Full HTML5 named-entity coverage is intentionally not claimed; verification is pending.

## QT-NOTES-008: Help text describes removed editor modes

- **Severity:** Medium; guide directs users to controls that no longer match the active editor.
- **Evidence:** `NotesHelpDialog.qml` contains a large paragraph that describes source/preview modes and unsupported structures staying in source mode, while the active worktree routes notes through a unified block editor and removes legacy source/preview QML surfaces.
- **Required fix:** Reconcile the guide with the current native block editor, including limitations still real today. Keep UI help in the Qt module and technical status in the audit docs.
- **Acceptance:** Every guide instruction names a visible control or keyboard action, and no removed mode is described as available.
- **Fix status:** Source fix applied in `NotesHelpDialog.qml`: removed instructions for source/preview modes and the obsolete Ctrl/Cmd+E shortcut. Verify the guide against the running UI and localization before closing.

## QT-NOTES-009: Table column movement rewrites row markup

- **Severity:** Medium; moving a column can lose table-row attributes or damage merged-cell structure.
- **Evidence:** Core `move_table_column()` reconstructed rows with a bare `<tr>` and reordered cell fragments without checking `rowspan`/`colspan`.
- **Required fix:** Keep row opening/closing markup and reject structural movement that cannot preserve merged cells or inconsistent row widths.
- **Acceptance:** Row attributes survive column movement; merged or malformed tables remain unchanged; ordinary tables move columns without losing content or formatting.
- **Fix status:** Source fix applied: row framing is preserved and Core returns the original table for inconsistent grids or merged spans. Runtime acceptance remains unverified.

## QT-NOTES-010: Slash command arguments do not reach native setup flows

- **Severity:** Medium; selecting a command can lose the user's typed data or initialize a modal with the command name as content.
- **Evidence:** React `useSlashCommand.ts` extracts command arguments before opening focus, alarm, event, habit, page-reference, and Scrap flows. The Qt editor previously passed the entire slash query to some setup modals, did not strip Portuguese/English aliases from page search, and opened Scrap with an empty URL even though the picker supports URL prefill and automatic capture.
- **Reproduction:** Enter `/foco 25 #Revisão Leitura`, `/alarme 15:30`, `/evento Prova`, `/habito Corrida`, `/page Minha página`, or `/scrap https://example.com`, select the matching command, and inspect the native dialog or captured URL.
- **Root cause:** Qt routed menu IDs but did not share React's longest-alias-first argument extraction contract with the setup and media dialogs.
- **Required fix:** Extract the remainder after the longest matching command alias; map focus duration/tag/description, alarm time, event title, habit query, page query, and Scrap URL into the native flow. Normalize a bare domain to HTTPS and leave invalid Scrap text editable without starting capture.
- **Fix status:** Source fix applied in `NotesSlashCommandArguments.js`, `NotesSlashCommandActions.js`, `NotesRichTextInput.qml`, `NotesEditorModalsHost.qml`, and `NotesMediaWidgetPickerModal.qml`. Per-command dialog, capture, cancellation, and persistence acceptance remains unverified.

## QT-NOTES-011: Focus slash form has different defaults and accepts incomplete data

- **Severity:** Medium; `/foco` opened with values that did not match React and could insert an unusable focus widget.
- **Evidence:** React `useSlashCommand.ts` defaults to 30 minutes with an empty tag and description. `focus/SetupModal.tsx` requires all three values and disables start until they are valid. Qt previously defaulted to 25 minutes and `Estudo`, then allowed insertion with an empty description.
- **Reproduction:** Select `/foco` without arguments and compare the form; then submit without entering a description or tag.
- **Required fix:** Use React's 30-minute, blank-tag and blank-description defaults. Keep insertion disabled until description/tag are non-empty and duration is a positive integer.
- **Fix status:** Source fix applied in `NotesSetupWidgetsModal.qml`. Runtime keyboard, validation and insertion acceptance is unverified; the command outcome mismatch is tracked separately in QT-NOTES-013.

## QT-NOTES-012: Native slash menu had mismatched geometry and command icons

- **Severity:** Low; command selection remained possible, but the menu differed in placement, sizing, padding, empty-state language, and icon concepts.
- **Evidence:** React `components/SlashMenu.tsx` uses a 288 px panel capped at 320 px, 56 px rows, 4 px list padding, a 33 px heading and Lucide icons. Qt used different header/row geometry, opened upward based on current menu height, had no list inset, and substituted several unrelated icons.
- **Required fix:** Align native dimensions, cursor overflow placement, and the fade/reveal, draw equivalent icon concepts, and match the Portuguese empty state without adding WebView/browser UI.
- **Fix status:** Source fix applied in `NotesRichSlashCommandMenu.qml` and `NotesSlashCommandIcon.qml`. Side-by-side screenshot, hover/keyboard state, stroke fidelity and text wrapping acceptance remain unverified.

## QT-NOTES-013: Focus and alarm slash actions have different outcomes

- **Severity:** High; selecting a command creates different application state across clients.
- **Evidence:** React `useSlashCommand.ts` opens `focus/SetupModal.tsx`; submit calls `handleStartTimer`, starting the global focus timer. Qt routes `/foco` to `NotesSetupWidgetsModal.qml`, whose submit inserts a paused inline focus widget. React `/alarme` opens `focus/AlarmSetupModal.tsx` and saves through `handleSaveAlarm`; Qt creates/selects an alarm and inserts an inline alarm widget.
- **Required fix:** Make the native slash flows produce the same timer/alarm state as React through the Qt/Core contract. Keep an inline note widget as a separate Notes action if it is not part of the React slash behavior.
- **Acceptance:** With identical inputs, both clients create/start the same timer or alarm record, show equivalent status, persist/reopen consistently, and do not create a Qt-only inline widget from the slash action.
- **Fix status:** Not fixed. Native controller/Core action contracts and timer/alarm behavior need a focused follow-up before command parity can be claimed.

## QT-NOTES-014: Widget HTML interpolation does not consistently escape entity characters

- **Severity:** Medium; names containing ampersands, angle brackets, quotes, or apostrophes can change value during HTML parse/serialize and metadata may not round-trip as typed.
- **Evidence:** `NotesSetupWidgetsModal.qml`, `NotesMediaWidgetPickerModal.qml`, and `BlockDelegateRouter.qml` assemble widget nodes from strings. Several paths escaped only double quotes or did not escape attribute values. The editor's dropped-file path had a narrower local escaper. React creates structured Tiptap nodes and does not construct these HTML strings in its UI.
- **Reproduction:** Create a habit, alarm, focus widget, or Scrap/file/media card whose title includes `A & B`, `<topic>`, or quotes; save, reload, and compare the original label and parsed attributes.
- **Required fix:** Use one Notes-local escaping helper for HTML text and quoted attribute values. Keep raw values for Core persistence and escape only at the HTML serialization boundary.
- **Fix status:** Source fix applied in `NotesHtmlEscaping.js` and used by the Qt editor, setup/media pickers, link dialog, and link-preview conversion. Recheck the complete Notes module for raw-HTML interpolation and validate metadata round-trip in Qt and React before closing.

## QT-NOTES-015: Native alarm setup accepts invalid time strings

- **Severity:** Medium; arbitrary text can be saved as an alarm time and embedded into a note widget, while React uses a native time input.
- **Evidence:** Qt `NotesSetupWidgetsModal.qml` used an unrestricted `TextField` and left the create button enabled. React `focus/AlarmSetupModal.tsx` uses `<input type="time" required>` and caps the optional label at 30 characters.
- **Reproduction:** Open `/alarme`, enter an invalid time such as `xx:yy`, and try creating an alarm.
- **Required fix:** Enforce 24-hour `HH:mm`, disable creation until the field is acceptable, and cap the label at 30 characters. Keep the raw accepted time for Core persistence and escape it only in the serialized widget attribute.
- **Fix status:** Source fix applied in `NotesSetupWidgetsModal.qml`. Verify intermediate typing, keyboard submission, Core rejection, and saved widget values at runtime; action semantics are tracked separately in QT-NOTES-013.

## QT-NOTES-016: Scrap URL detection accepts a domain prefix with trailing invalid text

- **Severity:** Medium; malformed input can be treated as a capture URL and fail only after the capture request starts.
- **Evidence:** The prior Qt helper and React flow both tested bare-domain patterns without anchoring the full string. Qt's native picker now reports validation errors before capture, so its preflight must reject `site.example trailing text` and protocol-only strings consistently.
- **Reproduction:** Select `/scrap site.example extra` or enter `https://` and start capture.
- **Required fix:** Accept complete HTTP/HTTPS URLs with a host, or complete bare domains (including a path/query) and normalize those to HTTPS. Leave invalid input editable and do not send a capture request.
- **Fix status:** Source fix applied in `NotesSlashCommandArguments.js`; URL edge cases and the controller capture boundary still require runtime verification.

## QT-NOTES-017: Calendar event card is not linked to the created event

- **Severity:** High; the note card cannot resolve or reflect the event that the slash command creates.
- **Evidence:** Qt `NotesSetupWidgetsModal.qml` calls `createCalendarEvent(...)`, whose C++/FFI contract returns only `bool`, then inserts `calendar-event-widget` without `data-event-id` or `data-page-id`. `CalendarEventWidget.qml::syncFromCore()` returns immediately when `eventId` is empty. React's `CalendarEventModal` receives the created event ID and inserts it with the page ID.
- **Reproduction:** Run `/evento Revisão`, save the modal, then inspect the note block attributes and change the event in its calendar record.
- **Required fix:** Keep creation in Core, return the created event ID through a typed bridge result, pass the current page ID, and serialize both IDs into the canonical note node. Handle recurrence explicitly so the note links to the intended occurrence/series.
- **Acceptance:** The block contains stable event/page IDs; reopening loads current title, time, color and status from Core; delete/missing-record and save failure show a recoverable state; React can read the same node.
- **Fix status:** Not fixed. The FFI currently discards Core's `CalendarEvent` ID and the QML card has no link ID.

## QT-NOTES-018: Event setup fields and defaults differ from React

- **Severity:** High; the same slash command produces different event dates, times, types and reminders.
- **Evidence:** React `CalendarEventModal.tsx` defaults to tomorrow at 14:00, uses a required title, exposes event type and four reminder options selected by default, and keeps the current page association. Qt currently defaults its date to today, has no time field, uses a fixed `event` type, offers a different single reminder choice, and does not pass a page ID.
- **Reproduction:** Open `/evento` in both clients at the same local date/time and compare the form, then save without editing values.
- **Required fix:** Match React's fields, defaults, validation, reminder selection and page binding while retaining the native QML implementation and Core persistence.
- **Acceptance:** Identical defaults and submitted event data, including timezone-aware start/end timestamps and all selected reminders; invalid/duplicate submissions are prevented and errors are visible.
- **Fix status:** Not fixed. Source review confirms the differences; same-viewport and data-level acceptance remains open.
