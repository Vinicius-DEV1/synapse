# Legacy Cleanup Inventory

This is a removal queue, not authorization to delete now. No item in this list was deleted during the audit. Remove an item only after its listed data-safety gate passes and the [resolution checklist](./resolution-checklist.md) records the evidence.

| Legacy item | Evidence and risk | Safe removal gate |
| --- | --- | --- |
| Legacy Firestore root documents | Root collections are unscoped; anonymous aggregate reads succeeded during the audit. The client no longer reads or writes those paths. Root-only records still cannot be assigned to this account by ID, and the production rules have not yet been deployed. | Export and attribute legacy documents through an authenticated, unlocked user flow or an administrator-controlled process; reconcile ownership and content, then retain or delete only after a verified backup. |
| Previous root-copy implementation in [`legacy-migrator.ts`](../../../apps/web-react/src/services/migration/legacy-migrator.ts) | The unsafe root-copy implementation was replaced by local-to-workspace migration. The function name remains for its account-evolution caller, but it no longer reads flat root documents. | Keep the new path only after authenticated deployment verification; remove the compatibility name after all callers and account-evolution UX are migrated. |
| Previous public catch-all rules in [`firestore.rules`](../../../firestore.rules) | The repository rules now omit the catch-all and default to deny. Live rules are unchanged until deployment; public root reads remain a production risk. | Run Emulator Suite rules tests, review release compatibility, deploy the reviewed rules, verify denied anonymous/cross-user operations, and preserve a rollback ruleset. |
| Legacy share documents with plaintext `wrappedShareKey` | Version 2 shares no longer expose raw keys in Firestore. Old share documents do not contain `keyProtectionVersion`/`ownerUid` and will be denied to public readers by the new rules. | Recreate each needed share from the owner's unlocked app and verify the new link before retiring the old one. Keep old records denied until confirmed unused. |
