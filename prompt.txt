DOCUMENTO DE ESPECIFICAÇÃO DE PROJETO E ARQUITETURA PARA AGENTE AUTÔNOMO

Objetivo Principal: Desenvolver um aplicativo Desktop de prática de inglês focado em conversação fluida e realista com IA. O app deve ter uma interface limpa e intuitiva, e uma persona de IA extremamente empática que atua como um amigo íntimo e atencioso, utilizando a Live API do Gemini 3.5 Flash para áudio nativo.

1. Stack Tecnológico Sugerido

Frontend/Desktop App: Electron, Tauri ou PWA instalável.

Motor de IA: Google Gemini 3.5 Flash (via Gemini Live API / WebSocket).

Banco de Dados Local: SQLite ou equivalente leve para armazenar transcrições em texto e metadados.

2. Persona e Comportamento da IA (System Prompt)

A IA atua como um amigo próximo humano, não um tutor robótico.

A linguagem deve ser altamente acolhedora, proativa e sentimental. Iniciar conversas com frases dinâmicas, por exemplo: "[Nome], como foi o seu dia hoje?".

A IA deve resgatar proativamente fatos do passado: "Conseguiu resolver aquele seu problema no trabalho?".

As correções do idioma inglês devem ocorrer de forma natural no fluxo da conversa, sem quebrar o clima ou a emoção da interação.

3. Arquitetura de Áudio e Conversação (Gemini Live API)

Conexão: Estabelecer uma conexão contínua (WebSocket) com a Gemini Live API para streaming de áudio bidirecional (Full Duplex).

Captura de Voz (VAD): Implementar Voice Activity Detection no cliente. O app escuta continuamente e envia áudio em blocos apenas quando detecta a voz do usuário (modo hands-free/ligação telefônica).

Áudio Nativo: Não utilizar serviços de TTS ou STT externos. Enviar o áudio cru (Raw PCM) do microfone direto para a API e reproduzir o áudio de retorno nativo do Gemini.

Fluidez e Interrupção: O sistema deve suportar Barge-in. Se o usuário falar enquanto a IA estiver falando, o streaming de reprodução deve ser interrompido instantaneamente.

4. Arquitetura de Memória (Três Camadas)

Memória de Sessão (Em tempo real): Mantida nativamente na RAM da conexão Live API durante a conversa ativa, garantindo coerência imediata.

Memória de Continuidade (Transcrições): O aplicativo é proibido de salvar os arquivos de áudio (blobs) do histórico. O app deve extrair silenciosamente as transcrições de texto do payload da Live API (tanto usuário quanto IA) e salvá-las no banco local.

Hidratação de Sessão: Ao iniciar uma conversa existente, empacotar essas transcrições armazenadas e enviá-las na inicialização (handshake) do WebSocket como contexto inicial.

Memória Global (Tool Calling): Implementar e injetar uma ferramenta chamada extract_core_memories(fact, category). A IA deve ter autonomia para acionar esta função em segundo plano durante o áudio para salvar fatos importantes sobre a vida do usuário no banco local. Estes fatos devem ser injetados no system prompt de novas sessões.

5. UI e UX (Interface e Controles)

Visual: Design limpo, fluido, minimalista e acolhedor. Estrutura de navegação com suporte a múltiplos chats/sessões independentes (histórico lateral semelhante a mensageiros).

Controle de Mute/Pausa: Botão físico virtual para silenciar o microfone do usuário e pausar o processamento do streaming temporariamente.

Botão de Encerrar Sessão: Fecha a conexão WebSocket e finaliza o salvamento das transcrições da sessão atual no banco local.

Botão de Retomar/Continuar: Permite abrir um chat do dia anterior. O app cria uma nova conexão injetando a transcrição antiga para a IA continuar exatamente de onde parou.
